# stem-hub 产品化文档重构设计

- 日期：2026-08-31
- 状态：待用户审阅
- 适用对象：以使用 stem-hub 模块的上位机/系统集成工程师为主，以现场操作人员为辅

## 1. 背景与问题

现有《设备固件与上位机集成交接文档》能够说明 AT 指令、固件任务和内部逻辑，但整体仍以“固件源码交接”为中心。stem-hub 作为一个对外交付的产品模块时，使用方首先需要知道模块能做什么、如何接入、如何完成典型业务流程、出现异常时如何恢复，AT 指令和内部任务应分别作为接口参考和补充说明。

本次重构将文档从“解释固件怎么实现”调整为“指导客户如何正确使用模块”，并保留协议细节和必要的实现约束，便于上位机稳定集成。

## 2. 设计目标

1. 让集成工程师无需阅读源码即可完成通信接入、状态同步、业务控制、异常处理和验收。
2. 用产品功能和标准工作流组织主文档，AT 指令作为实现这些工作流的接口手段。
3. 为现场操作人员提供独立、简短、可直接执行的操作说明。
4. 建立明确的单一信息源，避免命令格式、返回值和错误码在多个文件中重复维护。
5. 保留对上位机行为有实际影响的固件机制，例如异步事件、状态切换、保护动作和复位行为。

## 3. 本次不包含的内容

本次暂不编写以下硬件集成内容：

- 供电范围、功耗和电源时序；
- 接插件型号、针脚定义和线束要求；
- UART 物理电平与隔离要求；
- 机械尺寸、安装方式和环境等级；
- 硬件原理图、PCB 设计与维修指导。

文档中只保留已经能够从固件和现有资料确认的串口通信参数，并明确提示硬件信息需以独立硬件规格书为准。

## 4. 读者与使用场景

| 读者 | 主要目标 | 推荐入口 | 不要求掌握 |
| --- | --- | --- | --- |
| 上位机/系统集成工程师 | 建立通信、编写驱动、实现业务流程和故障恢复 | 《stem-hub 模块集成与使用说明》 | RTOS 任务实现细节、GPIO/ADC 底层代码 |
| 协议开发与联调人员 | 查询精确命令格式、参数、响应和错误码 | 《上位机 AT 命令文档》 | 完整产品操作流程 |
| 现场操作与测试人员 | 启动、运行、停止、识别状态并处理常见故障 | 《stem-hub 模块操作说明》 | RTOS、队列、内部驱动和完整 AT 指令集 |
| 固件维护人员 | 理解产品对外承诺并核对实现 | 三份文档及源码 | 无 |

## 5. 目标文档体系

### 5.1 主文档：`stem-hub模块集成与使用说明.md`

定位为产品随附的主要使用说明，面向上位机和系统集成工程师。它回答“模块是什么、怎样正确使用、上位机应怎样组织业务逻辑”。

建议目录：

1. 文档说明与适用版本；
2. 产品概述与能力边界；
3. 模块与上位机的职责划分；
4. 快速接入；
5. 产品功能与状态模型；
6. 标准业务流程；
7. 上位机集成规则；
8. 安全保护与异常恢复；
9. 联调、验收与故障排查；
10. 兼容性和版本维护；
11. 附录：简化的固件运行机制。

主文档中的“快速接入”至少包含：

- 串口配置和报文结束方式；
- 连接后进行版本确认和初始状态同步的顺序；
- 从发送请求到收到响应、再到状态确认的最小闭环示例；
- 上位机首次接入检查清单。

主文档中的“产品功能与状态模型”以外部可观察行为描述：

- OFF、CHARGE、DRIVE 等工作状态及允许的切换关系；
- 电机控制；
- NMOS、灯光和功率电阻旁路控制；
- 温度、电压、电流等状态采集；
- UART2/UART3 下游通信能力。

主文档中的“标准业务流程”按任务组织，而不是按命令字母顺序组织：

- 建立连接并同步状态；
- 进入和退出充电模式；
- 进入和退出驱动模式；
- 启动、调节和停止电机；
- 与下游串口设备通信；
- 安全停止与断开连接。

主文档中的“上位机集成规则”明确：

- 同一控制通道上的命令应串行发送；
- 同步命令响应与异步事件必须分别路由；
- 收到 `OK` 只表示命令被接受时，仍需通过状态查询或事件确认最终状态；
- 每条请求都应设置超时、重试上限和失败后的状态重同步；
- 断连、设备复位或协议解析失步后，上位机必须重新完成版本确认和状态同步；
- 保护事件优先于普通业务结果处理。

### 5.2 协议参考：`上位机AT命令文档.md`

定位为 AT 接口的权威参考，面向驱动开发和联调人员。它回答“每条命令的精确格式和协议行为是什么”。

该文件保留并统一维护：

- 通信格式、大小写、分隔符和结束符；
- 每条命令的语法、参数范围、同步响应和异步响应；
- 错误码、触发条件和建议处理方式；
- 会改变运行状态或涉及异步处理的命令语义；
- 必要的协议示例和解析注意事项。

该文件不重复完整产品介绍、操作流程和内部任务说明，而是链接到主文档。

### 5.3 操作说明：`stem-hub模块操作说明.md`

定位为独立的现场使用手册，面向操作和测试人员。它回答“如何操作、看到某种状态时该怎么办”。

建议目录：

1. 产品用途和操作前提；
2. 连接和启动确认；
3. 充电操作；
4. 驱动操作；
5. 电机启动、调节和停止；
6. 状态和故障提示说明；
7. 过温、堵转、通信中断等异常处置；
8. 停机和断开步骤；
9. 禁止事项与安全提醒。

操作说明使用动作导向的短步骤，不展开 RTOS 任务、队列、GPIO、ADC 或完整 AT 指令表。确有必要展示指令时，只给出完成某个操作所需的最小示例，并链接到协议参考。

### 5.4 项目入口：`README.md`

README 只承担导航职责，为三类读者提供清晰入口，并说明文档的推荐阅读顺序。

## 6. 文件迁移与命名

实施时执行以下调整：

| 当前文件 | 处理方式 | 目标 |
| --- | --- | --- |
| `设备固件与上位机集成交接文档.md` | 重构并更名 | `stem-hub模块集成与使用说明.md` |
| `上位机AT命令文档.md` | 保留并调整定位、交叉链接 | 协议权威参考 |
| 无 | 新建 | `stem-hub模块操作说明.md` |
| `README.md` | 更新文档入口 | 指向三层文档体系 |

旧文件名不再作为正式入口，以避免“源码交接文档”与“产品使用说明”并存造成读者选择困难。项目内指向旧文件的链接需同步替换。

## 7. 内容归属和单一信息源

为避免文档漂移，采用以下规则：

| 信息类型 | 唯一权威文件 | 其他文件的处理方式 |
| --- | --- | --- |
| 命令语法、参数、响应、错误码 | `上位机AT命令文档.md` | 只引用必要命令和链接 |
| 产品能力、状态模型、集成流程、恢复策略 | `stem-hub模块集成与使用说明.md` | 操作说明只做简化描述 |
| 现场操作步骤和用户可见故障处置 | `stem-hub模块操作说明.md` | 主文档提供概览和链接 |
| 固件内部任务与调度机制 | 主文档附录 | 只保留会影响外部交互的简化说明 |
| 硬件电气与机械规格 | 后续独立硬件规格书 | 本次明确标注不在范围内 |

主文档不复制完整命令表，操作说明不复制错误码全集。涉及相同概念时，通过相对链接指向权威章节。

## 8. 现有内容的重构原则

现有交接文档中的内容按以下方式处理：

- 产品能力、状态切换、保护逻辑、上位机交互原则和联调检查项：保留并改写为外部使用视角；
- AT 命令逐项说明和错误码细节：收敛到协议参考，主文档只保留工作流所需引用；
- 固件任务、队列、事件组、栈大小和底层资源表：不进入正文；仅把会影响响应时序、异步事件和保护行为的部分压缩到附录；
- 源文件路径、函数名和实现位置：从产品正文移除，除非其对固件维护人员核对行为确有必要；
- 测试建议：改写为客户可执行的接入验收清单和典型故障排查步骤。

文档表述以“外部可观察、可验证的行为”为准。不能从源码或现有资料确认的产品承诺不写成确定结论。

## 9. 导航与阅读路径

三份文档顶部均提供“适合谁阅读”和相关文档链接：

- 初次集成：README → 模块集成与使用说明 → AT 命令文档；
- 协议查询：README 或主文档 → AT 命令文档；
- 现场操作：README → 模块操作说明；
- 故障联调：操作说明中的现象处理 → 主文档的异常恢复 → AT 文档中的精确错误定义。

## 10. 验证方式

实施完成后进行以下验证：

1. 对照固件源码复核状态、命令、响应、错误码、异步事件和保护动作；
2. 检查主文档是否能够独立指导一次完整接入，不依赖读者理解源码；
3. 检查操作说明是否不包含不必要的实现细节；
4. 检查命令格式和错误码是否只以 AT 文档为权威来源；
5. 检查 README 和三份文档之间的相对链接；
6. 运行 Markdown 链接检查和 `git diff --check`；
7. 若改动触及协议事实，运行已有协议测试，并复核构建结果，确保文档与当前固件一致。

## 11. 验收标准

- 主文档首要呈现产品用途、能力、快速接入和标准流程，而不是固件任务结构；
- 集成工程师可从主文档得到初始化、命令调度、异步事件、超时恢复和安全处理规则；
- 协议开发人员可在 AT 文档中查到全部公开命令及其精确定义；
- 操作人员可在独立操作说明中完成启动、运行、停止和常见异常处置；
- 三份文档职责清晰，没有相互冲突的命令或错误码定义；
- 所有项目内文档链接有效；
- 硬件电气、连接器和机械内容明确标记为本次范围之外；
- 文档描述与当前源码和测试结果一致。

## 12. 实施边界

本设计只重构产品文档，不修改固件代码、AT 协议行为、硬件设计或现有测试逻辑。若重构过程中发现源码行为与现有协议说明冲突，应先记录差异并由产品/固件负责人确认，不通过文档改写擅自改变对外行为。
